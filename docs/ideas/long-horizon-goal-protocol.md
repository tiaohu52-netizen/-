# 远期目标协议：产品一页纸

> 本文是非规范性产品摘要。规范性定义以 [LHGP-SPEC.md](../LHGP-SPEC.md) 为准。

## Problem Statement

我们如何让用户把一个跨天、跨会话、甚至跨 Agent 应用的结果交给 AI 推进，而不要求原会话持续在线，也不把它降格成固定时间触发的 cron job？

## Recommended Direction

构建 **远期目标协议（Long-Horizon Goal Protocol，LHGP）**：一层独立于会话、模型与 Agent 应用的目标承诺运行时。用户与 AI 共同形成一份合同，写明结果、验收、Deadline、权限、预算以及可用的 CLI/模型；协议持有合同，Agent 只承办一次可替换的执行尝试。

产品的核心不是“让一个 Agent 跑很久”，而是“让目标不再属于任何一个 Agent”。协议保存可审计进度、在授权池内选择或更换执行者、编译最小上下文、提前判断 Deadline 风险，并由独立验收决定是否完成。

一句话：**会话持有一次尝试，LHGP 持有长期承诺。**

## Key Assumptions to Validate

- [ ] 用户愿意在立约时确认可核对的结果、权限和 Deadline——用 10 个真实目标测试合同准备流程是否能在 5 分钟内完成。
- [ ] 两个不同 Agent 能仅凭 Goal Capsule 和证据账本无损接力——关闭原会话后，用另一 CLI 完成同一目标并盲测结果。
- [ ] Deadline 风险提示能让用户更早调整范围或资源——对至少 20 次运行记录预测风险与实际完成时间，检查校准误差。
- [ ] 独立 verifier 能降低“模型自报完成”的假阳性——对相同交付物比较自报完成率与结构化验收通过率。

## MVP Scope

- 单机、单用户、本地 SQLite 权威状态。
- 每合同显式选择允许的 CLI、模型和角色。
- 串行接力；守护进程重启后可重连或安全回收外部尝试。
- 可重建 Goal Capsule、结构化 checkpoint/handover、租约与 fencing。
- 事件驱动 Deadline 风险控制；无动作时不调用模型。
- verifier 失败后 repair → 新 verifier 的闭环。
- CLI + MCP + 一个符合 Codex 结构的插件包。

## Not Doing (and Why)

- **承诺模型必然按时完成**——模型、网络、机器和任务难度不可控；协议承诺提前暴露风险和不静默违约。
- **多机 CRDT 调度**——它很诱人，但不是验证“目标独立于会话”的最短路径。
- **自动任意切分并行工作**——并行写冲突和验收合并会掩盖核心连续性问题，MVP 先做可靠串行接力。
- **完整聊天记忆产品**——LHGP 保存的是目标所需的证据化工作状态，不是用户所有对话历史。
- **工作流 DSL**——计划应能被 Agent 修订；协议只固定合同边界和提交规则，不预写完整执行图。
- **复杂 UI 与模板市场**——先证明协议语义和恢复能力，CLI/MCP 足够验证。

## Open Questions

- 公开产品是否直接使用 `LHGP`，还是采用独立品牌名、把 LHGP 仅作为协议名？
- v1 是否需要跨机器，还是保持 local-first 并允许第三方实现远程 runtime？
- 模型成本如何统一计量：由适配器上报实际费用，还是仅使用调用次数/时间预算？
